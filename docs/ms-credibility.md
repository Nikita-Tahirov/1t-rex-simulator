# Оценка доверия к модели 1T-REX

Документ задаёт рамку проверки и валидации для симулятора как модели и симуляции. Цель — не заявить внешнюю сертификацию, а сделать доверие к результатам проверяемым: каждое допущение, тест и эксперимент должны иметь источник, версию и критерий принятия.

Методическая база: NASA-STD-7009B и NASA-HDBK-7009B для оценки доверия к моделям и симуляциям, плюс WCAG 2.2 для доступности операторского интерфейса.

## 1. Контекст использования

| Поле | Значение |
|---|---|
| Назначение | ВКР-симулятор для демонстрации, отладки логики управления, сравнения сценариев и подготовки переносимых модулей |
| Недопустимое использование | Сертификация физического образца, расчёт безопасности удара, прогноз разрушения конструкций, принятие решений о реальном боевом применении |
| Критичность | Средняя для академических выводов; низкая для эксплуатации с требованиями безопасности |
| Model version | `1trex-ms-v1` |
| Log schema | `schemaVersion = 1` |
| Reproducibility seed | хранится в JSON-логе как `seed` |

## 2. Факторы доверия

| Фактор | Реализация в проекте | Статус |
|---|---|---|
| Requirements | Требования и границы применимости зафиксированы в этом документе, [architecture.md](./architecture.md), [assumptions.md](./assumptions.md) | закрыто для ВКР-уровня |
| Conceptual model | Слои панели индикации / автономности / управления / сенсоров / физики описаны в [architecture.md](./architecture.md) | закрыто |
| Mathematical model | PID, мотор, АКБ, skid-steer, IMU, фильтры и FSM описаны в [models.md](./models.md) | закрыто |
| Code verification | `npm run ci`: Biome, TypeScript strict, Vitest unit-тесты | закрыто |
| Numerical reproducibility | Сценарии получают фиксированный `seed`; `searchAndStrike` больше не использует `Date.now()` | закрыто для сценариев |
| Results traceability | JSON-лог содержит `schemaVersion`, `appVersion`, `modelVersion`, `scenarioId`, `seed`, телеметрию и метрики | закрыто |
| Validation against real data | Нет калибровочных прогонов физического 1T-REX | открыто |
| Uncertainty quantification | Протокол 10 seed-прогонов описан в [experiments.md](./experiments.md), но численные серии ещё не сняты | открыто |
| Независимая экспертиза | Не выполнялась внешняя экспертиза модели | открыто |

## 3. Критерии приёмки

| ID | Критерий | Проверка |
|---|---|---|
| MS-REQ-001 | Сборка без type/lint/unit ошибок | `npm run ci` |
| MS-REQ-002 | Релизная сборка без CSS/chunk warnings, кроме осознанных предупреждений зависимостей | `npm run build` |
| MS-REQ-003 | Ручное управление движет робота вперёд, вращает и останавливает после отпускания | `npx playwright test` |
| MS-REQ-004 | Панель индикации имеет машинно проверяемую доступность WCAG A/AA | axe-аудит в Playwright |
| MS-REQ-005 | Лог сценария содержит seed, версии и поля для восстановления табличных метрик | `ScenarioLogPayload` в [scenario-store.ts](../src/store/scenario-store.ts) |
| MS-REQ-006 | Сценарии не используют часы реального времени для начальных условий | проверка кода + `searchAndStrike(seed)` |
| MS-REQ-007 | Каждое численное значение в главе 4 выводится из сохранённого лога, а не вводится вручную без источника | [experiments.md](./experiments.md) + `npm run scenario:analyze` |
| MS-REQ-008 | Сценарий засчитывается только при совпадении целевого и фактического поведения | `verification` в JSON-логе + `npm run scenario:verify` + e2e-проверочный шлюз |

## 4. Долг валидации

Эти пункты нельзя закрыть только кодом:

1. Снять реальные данные 1T-REX: разгон/торможение, токи, температура моторов, напряжение АКБ, радиусы разворота.
2. Подобрать параметры модели по данным и зафиксировать процедуру калибровки.
3. Провести слепую валидацию: отдельный набор прогонов, не использованный при подборе параметров.
4. Оценить неопределённость: минимум медиана, min-max и доверительный интервал по seed-сериям.
5. Провести независимую экспертизу допущений, модели, кода и результатов.

До выполнения этих пунктов корректная формулировка статуса: **реализована рамка доверия, вдохновлённая NASA-7009; внешняя валидация ожидается**.
