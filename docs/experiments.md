# Экспериментальные исследования

Документ фиксирует состав сценариев, источники данных и шаблоны таблиц для главы 3 ВКР. Численные значения в текст работы переносятся только из реально выгруженных JSON-протоколов трассировки с фиксированным `seed`, блоком `summary` и результатом `verification`. Визуальное впечатление от браузера и одно поле `status=completed` не считаются доказательством прохождения сценария.

## 1. Общие условия прогонов

- **Шаг физики:** `dt = 1/60` с.
- **Шаг записи протокола:** около 100 мс симуляционного времени.
- **Seed по умолчанию:** `20260428`.
- **Версии артефактов:** `schemaVersion`, `appVersion`, `modelVersion`, `scenarioId`, `seed`, `runId`, `recordedAt` записываются в каждый JSON.
- **Телеметрия:** позиция, yaw, speed, yawRate, spinnerRpm, АКБ, токи и температуры колёс, оценки фильтров, дальномер, FSM-состояние, события сценария, команды автопилота `pilotActive/pilotThrottle/pilotTurn/pilotBrake`.
- **Анализ:** `npm run scenario:analyze -- path/to/log.json`.
- **Независимая проверка:** `npm run scenario:verify -- path/to/log.json`.
- **Экспорт эталонных протоколов:** `npm run scenario:export` сохраняет PASS-логи в `docs/experiments/`; по умолчанию использует изолированный Vite на `127.0.0.1:5175`.
- **Проверка свежего экспорта:** `npm run scenario:export:check` пишет логи во временную папку и проверяет все 8 прогонов Node-верификатором.
- **Проверочный шлюз:** PASS возможен только если протокол подтверждает цепочку `команда автопилота → физический отклик → прогресс сценария → цель/summary`.

## 4. Правила переноса чисел в ВКР

1. Сначала запустить сценарий в браузере, Playwright-прогоне или пакетном экспорте `npm run scenario:export`.
2. Выгрузить JSON-протокол трассировки.
3. Выполнить `npm run scenario:verify -- path/to/log.json`.
4. Переносить в таблицу только значения из логов с `verification.passed = true`.
5. Если verifier вернул FAIL, в текст переносится причина отказа, а не успешная метрика из `summary`.

Для обновления эталонов перед сдачей предпочтителен `npm run scenario:export:check`, затем `npm run scenario:export`: первый прогон проверяет свежесть экспортёра без записи в docs, второй фиксирует воспроизводимые PASS-артефакты. Verifier не принимает один `summary`: он сверяет активность автопилота, физический отклик, плотность лога, отсутствие телепортов, сценарный прогресс и целевые события.

Такой порядок нужен, чтобы ВКР доказывала фактическое поведение робота: команды автопилота, физический отклик, прогресс по миссии и достижение цели проверяются машинно и воспроизводимо.
