# 1T-REX Simulator

[![verify](https://github.com/Nikita-Tahirov/1t-rex-simulator/actions/workflows/verify.yml/badge.svg)](https://github.com/Nikita-Tahirov/1t-rex-simulator/actions/workflows/verify.yml) [![deploy](https://github.com/Nikita-Tahirov/1t-rex-simulator/actions/workflows/deploy.yml/badge.svg)](https://github.com/Nikita-Tahirov/1t-rex-simulator/actions/workflows/deploy.yml) [![live](https://img.shields.io/website?url=https%3A%2F%2Frex-1t.web.app&label=live%20demo&up_message=rex-1t.web.app)](https://rex-1t.web.app) [![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE) ![node](https://img.shields.io/badge/node-%E2%89%A524.15-brightgreen)

Программная часть магистерской выпускной квалификационной работы по программе **«Программирование интеллектуальных роботов»** (ПИР24-1м, Финансовый университет, 2026). Цифровой двойник боевого робота **1T-REX** команды «1Т» (Саратов) — веб-симулятор, реализующий контур управления, автономность и сенсорную обработку с машинно-проверяемой доказательной базой.

**Запущенная версия**: <https://rex-1t.web.app>

## Тема и постановка задачи

**Тема ВКР**: разработка и экспериментальное исследование программного контура управления и автономности боевого робота 1T-REX с применением методов цифрового двойника.

**Объект исследования**: боевой робот 1T-REX — полноразмерная машина массой 110 кг, 4WD skid-steer привод, вертикальный ротор до 7000 об/мин, аккумулятор 12S Li-Po (44.4 В).

**Предмет исследования**: программная архитектура управления и автономности робота, представленная в виде воспроизводимого цифрового двойника с независимой машинной верификацией поведения.

**Цель работы**: спроектировать и доказательно валидировать переносимую программную реализацию контура управления, сенсорной обработки и автономности, пригодную для прямого переноса на целевую микропроцессорную платформу МК МИК32 «Амур» без переписывания доменной логики.

**Задачи**:

1. Построить чистые TypeScript-модели физических подсистем (ПИД, мотор, аккумулятор, шасси), не зависящие от среды исполнения и переносимые на C/C++-прошивку.
2. Реализовать и сравнить два алгоритма оценки ориентации (комплементарный фильтр и фильтр Маджвика) на едином зашумлённом IMU-источнике.
3. Реализовать и сравнить две архитектуры автономного поведения — конечный автомат (FSM) и дерево поведения (BT) — на единой задаче поиска и поражения цели.
4. Сформировать рамку машинно-проверяемой верификации сценариев (V&V) по принципу «команда автопилота → физический отклик → прогресс миссии → событие цели», вдохновлённую NASA-STD-7009B.
5. Получить воспроизводимые JSON-протоколы экспериментов с фиксацией версий, сидов и верификационных метрик; обеспечить независимую CLI-проверку без браузера.

## Методы и реализация

| Метод | Назначение | Реализация |
|:--|:--|:--|
| ПИД-регулирование | Поддержание заданной линейной и угловой скорости шасси с anti-windup и асимметричным clamp ускорения | [src/control/pid.ts](src/control/pid.ts), [src/physics/robotBodyPid.ts](src/physics/robotBodyPid.ts) |
| Skid-steer 4WD | Кинематика 4-колёсного дифференциального шасси с независимыми приводами | [src/physics/kinematics.ts](src/physics/kinematics.ts), [src/control/drivetrain.ts](src/control/drivetrain.ts) |
| Модель щёточного мотора | Линейная характеристика $\tau(\omega)$, EMF, КПД редуктора, тепловая динамика | [src/control/motor.ts](src/control/motor.ts) |
| Модель АКБ 12S Li-Po | OCV-таблица, внутреннее сопротивление, brownout-просадка под нагрузкой | [src/control/battery.ts](src/control/battery.ts) |
| Комплементарный фильтр | O(1) оценка ориентации, низкая латентность | [src/sensors/complementary-filter.ts](src/sensors/complementary-filter.ts) |
| Фильтр Маджвика 6-DOF | Градиентный спуск, более точная оценка ориентации | [src/sensors/madgwick-filter.ts](src/sensors/madgwick-filter.ts) |
| Виртуальный IMU | Гауссовский шум, bias random walk, 16-битная квантизация | [src/sensors/imu-sensor.ts](src/sensors/imu-sensor.ts) |
| Энкодер колёс | Квадратурный сигнал с моделируемой дискретизацией | [src/sensors/encoder-sensor.ts](src/sensors/encoder-sensor.ts) |
| Планарный лидар | N лучей в горизонтальной плоскости вокруг forward-вектора для реактивного объезда | [src/sensors/lidar.ts](src/sensors/lidar.ts) |
| Конечный автомат (FSM) | Состояния `IDLE → SEARCH → ENGAGE → RECOVERY`, идентичны прошивке МИК32 | [src/autonomy/fsm.ts](src/autonomy/fsm.ts) |
| Дерево поведения (BT) | `selector { Emergency → Engage → Avoid → Patrol }` через DSL Mistreevous | [src/autonomy/behavior-tree.ts](src/autonomy/behavior-tree.ts) |
| Машинная верификация | Независимая проверка JSON-протокола по причинной цепи command → motion → progress → goal | [src/scenarios/verification.ts](src/scenarios/verification.ts) |

Все модули контура управления, сенсоров и автономности изолированы от React/Rapier/DOM — это обеспечивает прямой перенос на целевую платформу МК МИК32 «Амур». Физика симуляции выполняется решателем **Rapier 3D** (WASM SIMD, фиксированный шаг 1/60 с, 8 итераций) через `@react-three/rapier`.

## Эксперименты и результаты

Восемь сценариев пишут JSON-протоколы каждые 100 мс симуляционного времени. Каждый протокол содержит телеметрию, команды автопилота, события сценария и финальный блок `verification` с независимой проверкой инвариантов.

### Базовые миссии

| Идентификатор | Назначение | Метрика |
|:--|:--|:--|
| `figureEight` | Прохождение траектории Лиссажу вокруг двух конусов | Накопленное отклонение от эталонной кривой |
| `obstacleAvoidance` | Слалом через фиксированные барьеры от (−3,0) к (+3,0) | Время + 2 с × N столкновений; verifier требует 0 столкновений |
| `searchAndStrike` | Поиск и таран цели в кольце 3–4 м от старта | Время до контакта |
| `spinnerImpact` | Раскрутка ротора и удар по бронепанели | Время до удара при достаточной энергии контакта |

### Сравнительные эксперименты

| Идентификатор | Что закрывает в ВКР | Ключевые метрики |
|:--|:--|:--|
| `madgwickVsComplementary` | § 2.1.4 — сравнение алгоритмов оценки ориентации | `rmse_yaw_madgwick_deg`, `rmse_yaw_complementary_deg`, `ratio_comp_over_madgwick` |
| `fsmVsBt` (bt + fsm) | § 2.2.5 — сравнение архитектур автономного управления | `t_to_hit_sec`, `hit_succeeded`, `obstacle_collisions` |
| `brownoutDischarge` | § 2.1.2 — модель АКБ и компенсация просадки напряжения | `t_brownout_start_sec`, `min_v_load_v`, `final_soc`, `effective_power_loss_pct` |

Эталонные протоколы лежат в [docs/experiments/](docs/experiments/) — это первичный доказательный артефакт ВКР. Числа из `summary` напрямую входят в таблицы § 3.1 и приложений работы.

### Доказательный контур

```
ScenarioRunner ──► JSON-протокол ──► verifyScenarioLog() ──► verification: passed | failed
   (60 Гц физика,                       (independent CPU-only           (causal chain check:
    запись 10 Гц)                        verifier, no browser)           command → motion → progress → goal)
```

Цепь воспроизводима локально и через GitHub Actions:

- [scripts/export-scenario-traces.mjs](scripts/export-scenario-traces.mjs) — браузерный экспорт 8 PASS-протоколов.
- [scripts/verify-scenario-log.mjs](scripts/verify-scenario-log.mjs) — независимая CLI-валидация без браузера.
- [e2e/experiments.spec.ts](e2e/experiments.spec.ts) — Playwright-прогоны проверочного шлюза в реальном Chromium.

## Воспроизводимость

Требования: Node.js ≥ 24.15.0, npm ≥ 11.12.1. Среда разработки автора: i7-11800H + RTX 3080, Windows 11.

```bash
npm install
npm run dev               # http://127.0.0.1:5173 — интерактивная сцена
npm run scenario:verify -- docs/experiments/obstacleAvoidance.json   # независимая проверка протокола
npm run verify:fast       # полный проверочный шлюз локально (~4 мин)
```

Все JSON-протоколы фиксируют `schemaVersion`, `appVersion`, `modelVersion`, `scenarioId`, `seed`, `recordedAt` — этого достаточно, чтобы пересчитать любую таблицу ВКР. Сценарий `searchAndStrike` использует детерминированный seed (по умолчанию `20260428`), независимый от системного времени.

| Артефакт | Расположение | Команда воспроизведения |
|:--|:--|:--|
| 8 эталонных JSON-протоколов | [docs/experiments/](docs/experiments/) | `npm run scenario:export` |
| Свежий экспорт во временную папку + независимая проверка | системная temp | `npm run scenario:export:check` |
| Видеозапись прогонов | [docs/video/scenarios.mp4](docs/video/scenarios.mp4) | `npm run video:record` |
| Сборка production-бандла | [dist/](dist/) (после `build`) | `npm run build` |

GitHub Actions (`.github/workflows/verify.yml`) повторяет полный шлюз на ubuntu-latest при каждом push в `main`; деплой на Firebase Hosting автоматический.

## Научная новизна и практическая значимость

**Научная новизна**:

1. Рамка машинно-проверяемой V&V для боевых роботов по принципу NASA-STD-7009B, реализованная в виде независимого верификатора причинной цепи поведения по сохранённому JSON-протоколу (вместо доверия к UI-сводке).
2. Сравнительная количественная оценка комплементарного фильтра и фильтра Маджвика на едином зашумлённом IMU-источнике в условиях планомерного yaw-маневра (`madgwickVsComplementary`).
3. Сравнительная количественная оценка конечного автомата и дерева поведения на единой задаче поиска и поражения цели с регистрацией столкновений и времени до контакта (`fsmVsBt`).
4. Переносимая реализация контура управления, сенсоров и автономности в виде чистых TypeScript-моделей, не зависящих от среды исполнения, — пригодная к прямому переносу на МК МИК32 «Амур».

**Практическая значимость**:

- Инструмент отладки алгоритмов команды 1Т перед выездом на соревнования (BattleBots-турниры) без риска поломки физического образца.
- Воспроизводимые экспериментальные данные с фиксацией версий и сидов — пригодны для регрессионного тестирования при последующих изменениях.
- Доступная веб-демонстрация (`rex-1t.web.app`) для презентаций и образовательного применения.
- Open-source (MIT) — методология V&V и переносимые модели могут быть применены к другим робототехническим системам.

Подробное обоснование границ применимости и долг валидации описаны в [docs/ms-credibility.md](docs/ms-credibility.md).

## Структура проекта

```
src/
├── control/      ПИД, мотор, АКБ, drivetrain — переносимые TypeScript-модели
├── sensors/      IMU, энкодер, лидар, фильтры ориентации
├── autonomy/     FSM и BT, общий контракт пилота сценария
├── physics/      Rapier-обёртки: робот, арена, ротор, камеры, контроль кинематики
├── scenarios/    Декларативные сценарии, runner, верификатор, manager
├── store/        Низкочастотное состояние (Zustand) + телеметрия (Valtio)
├── hud/          Панель индикации: полётная, сенсорная, инженерная вкладки
├── monitoring/   ErrorBoundary, performance hooks
├── lib/          Общие утилиты: clamp (math.ts), createRafSampler
├── offline/      Регистрация service worker, offline fallback
└── theme/        Дизайн-токены и цветовая палитра

docs/             Документация ВКР: архитектура, модели, допущения, эксперименты, V&V
e2e/              Playwright + axe: drive, collision, experiments, HUD, performance
scripts/          Шлюзы verify, экспорт сценариев, видео, сборка GLB
public/           GLB-модели робота, Draco-декодер, иконки PWA
robot/glb-source/ Исходные несжатые GLB корпуса, ротора, колеса
```
